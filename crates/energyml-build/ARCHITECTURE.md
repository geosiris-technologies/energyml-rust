# energyml-build — architecture

Related decisions: [ADR 0017](../../docs/adr/0017-operation-is-a-pure-function.md) (an operation is a pure function; only `apply` writes), [ADR 0018](../../docs/adr/0018-synthetic-reference-model.md) (the synthetic reference model, played by a recipe), [ADR 0003](../../docs/adr/0003-identity-full-uri-one-door.md), [ADR 0005](../../docs/adr/0005-refuse-rather-than-draw.md), [ADR 0006](../../docs/adr/0006-registries-rather-than-match.md), [ADR 0011](../../docs/adr/0011-tests-follow-the-specification.md), [ADR 0012](../../docs/adr/0012-no-face-carries-logic.md), [ADR 0014](../../docs/adr/0014-horizons-units-attachments-constraints.md), [ADR 0016](../../docs/adr/0016-one-crate-one-test-binary.md).

## Purpose and position

Creating EnergyML objects through **one door**. An operation turns a bag of inputs into a plan of objects; a registry offers, plans and applies them; recipes chain them into one package. Operations include CRS creation, wells and logs from tabular or JSON input, point sets and polylines from GeoJSON, surface interpolation and maps, contacts and tops from wells, IJK grids (with faults and properties), cross-sections, media attachment, and a GeoSciML GeologicUnit import (tested with SIGEOL exports). It sits above storage, domain, geometry and analysis; it compiles to WebAssembly (parsers and vocabularies only: network and disk I/O belong to the face). `energyml-build-derive` supplies the derives that declare operations.

The module map: `operation` (the trait and registry), `declare` / `describe` / `template` (slots, forms, activity templates), `pieces` + `read` + `assemble` + `build` (the bag and the plan), `apply` (the only writer), `ops/` (one file per operation, `ops/support.rs` shared), `entries` + `recipe` (running a sequence), `geojson`, `mesh`, `source`, `table` (inputs: a parser and a vocabulary each), `naming` (derived identity), `galaxy`, `manifest`.

## The core rules

- **An operation is a pure function from a bag to a plan.** `Operation::plan(pieces, choices, identity, when) -> Plan` receives no store; purity is held by the signature. What an operation knows of a package object arrives resolved in `pieces::Known`. Every operation is then testable with values, without a package. **`apply::apply` is the only code that touches storage**; it takes the concrete `EpcStore`, so a second storage backend is added there and nowhere else.
- **Declare once, with the derives.** Parameters are a `#[derive(Params)]` struct, inputs a `#[derive(Inputs)]` struct, a method an enum union (`#[params(tag = "…")]`). The field is the declaration; its doc's first paragraph is its label; defaults are written once. `plan` reads no name and knows no companion suffix. An operation that calls another goes through its typed write function (`polylines::write`, `triangles::write`, `grid::write`, `property::write`…), never through a derived bag.
- **Adding an operation: one file, one line, one template.** (1) a file in `src/ops/` implementing `Operation`; (2) its line in `ops::builtin()`, the only list; (3) its activity template in the shipped templates file with a new uuid. The slot is the source and the template a projection (`template.rs`): a test replays the projection against the file, so a slot added without its parameter fails. What EML cannot type (a closed choice, a bound, a flag: 2.3 has no boolean and no integer parameter) goes into a `Constraint`, in words. `needs()` must answer on any bag, the empty one included, since the template is projected from it.
- **A slot says three things about itself; the form writes none.** `Applies` (when can it act: `With` asks "will this slot have a value", answered or suggested; `Without` asks "has the other way been decided", answered only), `Otherwise::Creates` (what an empty slot produces; an optional slot that silently creates something must name it), and `Slot::reads` (reflective paths on an object of the same kind, for copy-from-similar). Groups (`frame`, `represents`, `operation`, `naming`) order the form; `Provenance` says where a proposed value came from. These live in the declaration, never in a UI, or the CLI and the UI would each hold a version of the same rule.
- **A suggestion can read only the bag, never another answer.** The registry settles absent slots from their suggestion *before* `plan` runs; a suggestion that depends on a choice silently gives every variant the same value. What depends on an answer is derived inside `plan`, and the slot stays optional while saying where the value will come from. A parameter title cannot be both an input and a report.
- **`takes()` declares inputs, `needs()` declares settings, and they are separate.** `takes()` takes no bag: what an operation takes does not depend on what was already given, which is what lets the form render before any choice. Its vocabulary is that of `Source::kind` (`shape`, `features`, `lattice`, `field`, `ramp`, `object`), never a second one. Declaring an input in both would project it as an input *and* a setting, which the template reads as a direction disagreement. A test builds, for each operation, the bag its declaration describes and demands that `fitness` finds it fit.
- **Cardinality is a wire format.** Anything that is not exactly `most: Some(1)` is a list (`Slot::takes_many()` is the one place that says so); `optional` (0..1) stays a value. `check_many` checks the shape first (a bare value in a multiple slot names the expected shape), then the count (with both numbers), then every element (all of them, not the first failure). An empty list is an absence. **Order is a third, declared fact** (`Slot::in_order`): taking several values says nothing about their order. A role is read from the slot's name, never inferred from topology: two polylines are indistinguishable by geometry, so a decoy test pins it.
- **Refuse by name, before any work.** The offer judges only the kind of piece (`fitness`); what a piece must additionally say (what a frame must carry, for instance) is the plan's to refuse, by name. `fitness` returns `Unfit(reason)`, never `false`; `Registry::offers` lists unfit operations *with* their reason (absent reads as "not written yet"); `Choices::settle` refuses a missing required slot and a wrongly shaped value before `plan`, one `Refusal { key, slot, message }` per faulty field, returned as data rather than raised so the structure survives a worker boundary. An operation that sets entities aside **counts** them in `Plan::dropped`; what it means to say goes in `Plan::says` as key + detail.
- **A plan can be asked for its geometry or for its writing** (`Purpose::Geometry` relaxes the slots outside the `operation` group). **Computing needs no CRS; writing does.** A missing or wrong frame makes the plan *blocked*, not refused: the plan still carries its shapes, and `apply` alone refuses (testing blockage before emptiness: "nothing to write" and "nothing could be written" are different news). A frame created in the plan is never blocked, since its systems are written in the operation's own release. A geometry plan computes in the scene frame, a writing plan reads local, and all objects of one plan share one frame.
- **Identity is a policy** (`Identity::Derived`, a v5 uuid of what the producer owns, so two runs of one input write the same package; `Identity::Given` otherwise). An operation that names from the producer refuses given uuids. The activity is always new: two runs are two events. **A number entering a seed goes through `support::seed_mm`** (millimetres, never the last bit): a reprojected coordinate carries the platform libm in its last bit, and a seed that wrote it raw derived different uuids on Windows and Linux for the same object. Content-derived identity beats file-name identity: the same content under another name must not duplicate the objects, and different content must add an object, not overwrite one.
- **An object is named by its full URI, never its uuid** (ADR 0003). `Ref` carries its version and its address (`Ref::uri`, the only way to make a URI); followed references go through `read::followed`, which returns `None` for an ambiguous uuid rather than "one of them"; a plan names its objects by URI. A version enters a seed only when it exists, so versionless packages keep their uuids. A `#<uuid>` on a command line is an input adapter.
- **An operation adds objects; it never edits one.** `apply` writes only the objects of the plan (an operation that transforms or resurfaces an input writes a fresh object and leaves the input untouched). An object written under an identity already present replaces it, and `Made::replaced` lists those URIs, since a package written twice from two sources is the ordinary case and the replacement must be visible, not silent. A different content has a different identity and is added beside: `Made` also reports titles written next to an object of the same title and type.
- **A slot that takes an object receives the answers of a form.** The binder gives the one object slot of an operation every object piece that no slot names (a CRS chosen in the form comes back as a `known` piece). An operation with such a slot therefore passes over, and counts, what is not of its kind where it was only landed there, and refuses it only when it was addressed to the slot by name.
- **What an operation writes is validated against the schema.** `apply` reads every planned object back as a typed object and `Made::invalid` names each error (object, path, rule). It is not a refusal (losing the requested work for a facet is worse than reporting), but an operation writing non-conforming data is a defect of the operation, and tests that apply a plan assert `made.invalid.is_empty()`.
- **Arithmetic is cross-checked against the calculation crate, not against the operation.** A test of a computed quantity (a flow law, a survey) compares the operation's output with `energyml-analysis` called directly, and reads every planned JSON back into its generated type before asserting anything of it; a component is never asked to grade its own work.
- **A calculation lives in `energyml-analysis`/`energyml-geostat`, never in an operation.** An operation that produces an object another one already writes delegates to it and signs the activity with its own name (a second writer would be a second place for the same errors). A computed thing is scriptable by being an operation: no separate "compute" command, because the create door already gives form, activity template and named refusals.
- **An activity records what was *said* at the run.** The registry writes every settled choice (suggestions included, since a second run would need them to output the same) into the activity parameters under its slot name; `exemplar::from_activity` reads it back, so "redo like this activity" is possible. An activity that does not record its inputs is a receipt, not provenance.
- **Outputs are declared by role** (`gives()`): `apply` groups by `NewObject::role`, the run manifest lists by it, and a Galaxy tool gets one URI output per role. A role a plan writes and `gives()` does not name is a defect (a test also requires every declared role to be seen). An operation composing others reuses their lists.

## Geometry and coordinates

- **A geometry names a compound CRS.** `crs::build` writes four objects in metres (`ProjectedCrs`, `VerticalCrs`, a `LocalEngineering2dCrs` embedding the projected one, and the `LocalEngineeringCompoundCrs` that joins plan and vertical); the role `crs` is always the object a geometry names. The default compound is the identity (origin 0/0, azimuth 0), so a number is what it was under the projected system. In degrees there is no compound (the origin must be a projected CRS) and the plan says so; a well in degrees is refused. A named frame is judged by `crs::frame_kind`: a compound or a 2.0.1 system as is; a projected CRS accepted with a note; a half (vertical only, local 2D only) blocks writing by name. The datum is written in the frame it is expressed in.
- **A shape is placed in the written frame inside `plan`** (`support::shape_placed`), never inside a `write` (those also receive computed, already-placed shapes). A named frame keeps the numbers; a frame created from `sourceEpsg`/`project` reprojects a file's shape and refuses a package's shape when numbers would move.
- **A lattice is not reprojected, and its order is the house order**: `z[j·ni + i]`, `i` along x fastest, the slow axis first in `Dimension`. A producer with the other order transposes before building the piece. A hole is a `NaN`, written as is and counted in a `holes` note.
- **A value stated per layer is the same on every cell of the layer**, whether or not that cell's geometry is defined (a fact about a layer is not a fact about a corner point); a cell without geometry has no location to read a depth from and is written `NaN`.
- **Copying a topology and deciding one are two operations.** `triangles` copies the triangles the input carries; `triangulate` decides them (2D Delaunay). Letting the first accept a cloud would silently invent what the input does not say; each refusal names the other operation. Collinear points are refused at computation, duplicates counted not refused.
- **Surface order in a cross-section is declared, and an inversion is reported, never corrected.** The order is the bag's (`in_order`), top to bottom, not deduced from mean elevation, which is wrong exactly where surfaces cross. An empty panel is an answer (counted and named); *no* panel is a refusal.
- **Geometry-free inputs are first-class.** `ObjectIn` carries any object (a table, a property kind, a colour map), a companion `X (object)` is "what we know of X" and is recognised by name, and continuing a category table keeps its uuid and its row order so the codes already written keep their meaning.
- **A selection by rings is a step, not an operation** (`selection.rs`): inside at least one `outer` (none = everywhere), inside no `inner`, with `inside` / `touches` / `head` modes; one implementation for every face.

## Sources and formats

- **A source is a path or an address, and its name is read in one place** (`source.rs`): it downloads nothing. An address is reduced to the file it names (last path segment, query and fragment removed, percent-escapes decoded) because imports read meaning *from the name*. Only `http` and `https`; the scheme decides, not the colon; the fragment is cut before the query.
- **A file name and a piece name are two facts** (`file` decides the format, `name` names the piece).
- **Mesh formats are one list** (`mesh::FORMATS`: obj, vtk, vtp, vtu, csv, geojson), decided by file extension, never sniffed; a refusal names the line; triangles and segments are separate patches on the same points, with correct node offsets. A format declares what the file cannot say (`Format::asks`: a height, a projection), but **the reader tries first and asks only if the refusal names a missing thing** (`Refused::missing`, filled where the refusal is born, never recognised from message wording). A CSV in lon/lat is refused naming the format that can read it. VTK XML reads `ascii` only; its `offsets` are cell ends, not lengths.
- **A vocabulary-specific import is its own module** (the GeoSciML reader and the borehole reader know nothing of each other; the shared part is the GeoJSON format).
- **Properties on a frame are positional**: exactly as many values as the frame has nodes, always, checked against its measured depths (the geometry and the node depths are two arrays of the file); otherwise the property is refused by name. The parameter of a trajectory is the measured depth, and the measured depths of a plan are written as the plan states them, never recomputed from chords. A law of depth is read at the *vertical* depth below the ground under the head, not from the datum and not along the hole. Columns of a table become one property each by default; `textColumns` and `everything` gather text columns (and columns no template names) into a `ColumnBasedTable`, one for the run or one per frame. A borehole already in the package is recognised by its title **and** its head position together; a recognised one receives only what it lacked. Enrichment does not overwrite: identity comes from content (feature and interpretation from the borehole name; trajectory and frame from the borehole and its depths; property from the borehole, the column *and its values*; a category table continues). An input slot marked `every` defaults to all matching objects of the target package (`read::every`, one implementation); an unreadable representation fails the fill, never passes as an absence.
- **Media is a part of the zip linked to its `Attachment`**; a form is deduced from what is given and refused on its slot otherwise; a depth goes only where one exists, with its unit checked against the closed list (the unit enumeration is open, so a stray word would otherwise become `Other`).

## Recipes

A recipe is a versioned TOML sequence of steps played in one in-memory store by `recipe::play`, **through the same path as `create` and no other** (`entries` reads files, `read::every` fills empty slots, `Registry::plan` with derived identity, `apply`). Inputs are files or what a previous step wrote, designated by step name and filtered by `type`/`title`/`role`, never a copied uuid. `Recipe::check` refuses everything before any planning (unknown operation, duplicate name, **a setting the operation does not declare**, an input from a future or pending step) and playing stops at the first refusal, so a half-made package is never saved. A step can be pending with a reason (reported, declared in the template, not played); a group switch yields variants without a second recipe. The recipe **is** the workflow: a derived activity template and a root activity name each step's activity, with uuids derived before the first step; the step name enters its activity's seed. The reference model it plays (ADR 0018) is replayed byte-for-byte on the platform that wrote it and compared up to float noise elsewhere, since different libm implementations differ by one ulp and a derived uuid follows a position.

## Not done

No network, disk or process I/O. No second storage backend in `apply` yet. No guessing: a lattice is never reprojected, an inverted section never reordered, a missing unit never assumed, no feature type invented when none was asked.

## Observability

The library emits `tracing` spans and configures nothing: **one span per phase** (`operation.plan` once in the registry, recipe steps, reading a source, writing, the costly phases of large operations), with counts as fields; never one event per element in a loop. A log is not a report: what the user must know (refusals, notes, dropped items) stays in the operation's report. A new operation needs nothing to be traced. An `init`, a `set_global_default` or a diagnostic `println!` in this crate is a defect.

## Tests

Single integration binary (`tests/main.rs`, `autotests = false`): a new test file is one `mod` line, or it does not run. A file that installs a process-wide default (a registry of dictionaries) keeps its own `[[test]]` binary and a test forbids the regression. Tests state rules on fabricated data (the specification governs the assertions, not a corpus). Notable tests: the projection of every operation's slots into its template; the `takes` declaration being fit; cardinality with an operation declared *inside the test* (a fake operation in the registry would be offered to someone); the decoy for role-by-name; the `gives` roles; Galaxy tools declare every variable the command uses and refuse unset optional parameters. Costly operations are in a benchmark (`benches/speed.rs`), outside the tests and CI.
